### CWE-798: Hardcoded credentials

- Identify a credential-like literal: a password, API key, access token, private key, or a connection string that embeds a password.
- Establish that the literal is assigned to a name, passed as a keyword argument, or embedded in a URL that a client will use to authenticate.
- Establish that the value is a real secret rather than a placeholder: a non-trivial literal that is not `""`, `"changeme"`, `"<your-key>"`, an obvious example, or a test fixture clearly marked as such.
- Do not report a variable name alone, a value read from the environment or a secret manager, a hash of a secret, or a constant used only for a non-authentication purpose (a public client ID, a format string).
- A key committed as a default argument or class attribute is still hardcoded; do not exclude it because it can be overridden at runtime.

#### Example

```python
# Redacted illustration; this placeholder is not a real key.
API_KEY = "XXXXXXXXXXXXXXXXXX"

def client():
    return connect(token=API_KEY)
```

#### Finding location

- The primary operation is the assignment or argument that embeds the credential literal. Cite the authentication use in `explanation`.
