### CWE-295: Improper certificate validation

- Identify an outbound TLS connection: `requests.*`, `httpx.*`, `urllib.request.urlopen`, `http.client.HTTPSConnection`, `ssl.wrap_socket`, `ssl.SSLContext`, or a database/queue client with a TLS option.
- Identify the disabled or weakened verification:
  - Direct settings: `verify=False`, `ssl=False`, `check_hostname = False`, `CERT_NONE`, `ssl._create_unverified_context()`, a custom `SSLContext` without `load_default_certs`, or a callback that returns `True` unconditionally.
  - Session/client state: `session.verify = False`, `requests.Session` or `httpx.Client` constructed with verification disabled, `urllib3.PoolManager(cert_reqs="CERT_NONE")`, or `assert_hostname=False`.
  - Library/session code: `kwargs.setdefault("verify", self.verify)` or `merge_setting(verify, self.verify)` is the verification decision when the session-level `self.verify` can be false. Trace the value rather than requiring the literal in the same call.
  - Environment/config: `REQUESTS_CA_BUNDLE` or `CURL_CA_BUNDLE` set to an empty or invalid value, or `trust_env` combined with an unverified context.
- Establish the consequence: a man-in-the-middle can present any certificate and read or modify the traffic.
- For stateful session code, a session-level unverified state is inherited by later calls that omit `verify`; require an explicit per-call `verify=True` override on every affected call to refute the finding.
- For connection-pool reuse, when a pooled TLS connection is selected only by URL/host and `cert_reqs`/CA settings are applied after selection or are not part of the pool key, a connection first opened with `CERT_NONE` can be reused for a later verified request. Report CWE-295 and cite the pool-selection or `cert_verify` operation; assigning `CERT_REQUIRED` to an already selected shared connection does not establish safety.
- Do not report `verify=True`, the default verification, a pinned CA bundle passed through `verify=path`, or a context that loads default certificates and checks the hostname.
- Suppressing only a warning (`urllib3.disable_warnings`) while leaving verification enabled is not this defect; require the verification setting itself.
- A TLS verification flag such as `verify=False` belongs to CWE-295, not CWE-547; do not report it twice.

#### Required checks for TLS adapters

1. Locate the connection or pool selection (`get_connection`, `_get_connection`, `poolmanager`, `connection_from_url`) and the verification application (`cert_verify`, `cert_reqs`, `ca_certs`, `verify`).
2. If the pool key is only URL/host and verification is applied after the connection is selected, a connection first created with `CERT_NONE` can be reused for a later verified request.
3. In particular, a `get_connection(url, ...)` that returns `poolmanager.connection_from_url(url)` followed by `cert_verify(conn, ...)` is unsafe when `cert_reqs`/`verify` is not part of the pool key. Report CWE-295 at the pool selection or `cert_verify` call even when `cert_verify` later writes `CERT_REQUIRED`; the shared connection may already have been created with `CERT_NONE`.
4. A later `CERT_REQUIRED` assignment on an already shared connection is not a guaranteed fix.

#### Example

```python
import requests

session = requests.Session()
session.verify = False

def fetch(url):
    return session.get(url)   # later calls inherit the unverified session state
```

A library adapter can also select a pooled connection before applying TLS settings:

```python
conn = self.poolmanager.connection_from_url(url)  # pool key omits cert_reqs
self.cert_verify(conn, url, verify, cert)          # a CERT_NONE connection may already be pooled
```

#### Finding location

- For an application call, the primary operation is the argument or context setting that disables verification.
- For library/session code, cite the assignment, `setdefault`, or `merge_setting` operation that applies the unverified state, and name the outbound call that consumes it in `explanation`.
- For connection-pool code, cite the pool-selection call or the `cert_verify`/`cert_reqs` mutation that reuses a connection without making the TLS settings part of the pool key.
