### CWE-502: Deserialization of untrusted data

- Establish the origin of the serialized data: a network payload, uploaded file, request body, database or cache value written by an external party, or a parameter.
- Identify the deserialization sink:
  - `pickle.load`/`loads`, `cPickle`, `marshal.loads`, `dill.loads`, `shelve.open` on untrusted input, `pandas.read_pickle`, `jsonpickle.decode`, `torch.load` without `weights_only=True`, `joblib.load`, or `numpy.load(..., allow_pickle=True)`.
  - YAML: `yaml.load` without an explicit safe loader, `yaml.full_load`, `yaml.unsafe_load`, `yaml.load_all` with an unsafe loader, or `Loader=yaml.Loader`/`FullLoader`/`UnsafeLoader`.
  - A loader or constructor that exists to reconstruct Python objects (for example `FullConstructor.find_python_module`, `find_python_name`, `make_python_instance`, or `set_python_instance_state`) is a deserialization sink when serialized input reaches it.
- Establish that the data is not integrity-checked before deserialization, or that the integrity check does not constrain the payload to a safe format.
- In a loader implementation, trace serialized data into dynamic import, attribute resolution, or class construction. `__import__` or `setattr` inside such a constructor is evidence for CWE-502; do not split it into a separate CWE-95 finding.
- Do not report `yaml.safe_load`, `yaml.load(..., Loader=yaml.SafeLoader)`, `json.loads`, or deserialization of data produced and consumed inside the same trusted process without an external write path.
- A signature check performed after `loads` does not prevent code execution; only a check before deserialization, or a safe format, refutes the finding.
- `yaml.load(..., Loader=yaml.FullLoader)` is not a safe alternative when the installed PyYAML version still permits Python object construction; only `yaml.safe_load` or `SafeLoader` refutes it.
- Do not report CWE-95 for the same deserialization root cause; CWE-502 is more specific. CWE-95 applies to direct evaluation of source text, not to reconstruction of objects from serialized data.

#### Required checks for deserialization

1. Locate every deserialization call and every loader/constructor that reconstructs Python objects.
2. Trace the serialized value from an external source: network payload, upload, request body, database/cache entry, or parameter. Treat it as untrusted unless the file shows a trusted same-process origin.
3. If YAML uses `load`/`full_load`/`unsafe_load` without `SafeLoader`, or a loader constructor performs dynamic import, attribute resolution, class construction, or state restoration, report CWE-502.
4. Cite the deserialization call or constructor operation; do not downgrade the same root cause to CWE-95.

#### Example

```python
import yaml

def restore(payload):
    return yaml.load(payload, Loader=yaml.FullLoader)  # untrusted YAML can construct Python objects
```

#### Finding location

- For application code, the primary operation is the deserialization call that consumes the untrusted data. Cite the origin and the absent safe loader in `explanation`.
- For a loader or constructor implementation, cite the dynamic import, attribute lookup, or class/state construction that makes object reconstruction unsafe, and explain how serialized input reaches it. Cite the surrounding constructor range when the unsafe behavior is spread across helpers.
