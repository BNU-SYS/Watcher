# CWE-502: Deserialization of Untrusted Data

Report when input crosses an untrusted deserialization boundary and constructs unsafe objects or violates required state invariants without effective restrictions.

1. Trace input to object construction or callbacks. For XML, YAML and JSON, establish the selected mode and how input influences types or state.
2. Check type allowlists, class resolvers, graph limits, authenticated envelopes and applicable process-wide filters at the construction boundary. A later cast cannot prevent earlier callbacks.
3. Follow relevant `readObject`, `readResolve`, constructors and conversion contracts. Distinguish supported side effects or state corruption from hypothetical gadget behavior.

Identify the input, construction mode, ineffective restriction and supported consequence. Locate construction or deserialization. Serialization declarations, API names and historical library CVEs alone are insufficient. Effective trust and restriction policies refute the corresponding path. Record essential unknown dependency or runtime behavior in `limitations`.
