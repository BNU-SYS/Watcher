# CWE-352: Cross-Site Request Forgery

Report a supported bypass of request-intent protection for a sensitive operation using ambient browser credentials. A dedicated anti-CSRF token API can establish a local protection contract.

1. Identify the action, credential flow and accepted cross-site request, or follow a token helper from generation through session storage and request comparison.
2. Check validation, session/user binding, replay handling, origin checks, middleware and applicable browser constraints.
3. Check token unpredictability separately from uniqueness. `java.util.Random` is a predictable PRNG. A long `BigInteger` token, encoding or low collision probability preserves that predictability. Trace the actual constructed generator and seed/state exposure. A `Random`-typed variable holding `SecureRandom` retains the latter's cryptographic behavior.
4. Give the bypass or concrete generation-contract failure and state any missing endpoint context separately. Effective unpredictable tokens and enforced binding refute the corresponding path.

Locate the decisive generation, comparison or exposed handler. Explicit bearer headers require an attacker-supplied credential path. Disabled CSRF configuration, CORS settings or absent local token checks alone are insufficient when effective middleware may apply. Record essential unknown protection layers in `limitations`.
