# CWE-835: Loop with Unreachable Exit Condition

## Report only when

A feasible local path preserves a loop's nonterminal state indefinitely. Account for all reachable exits, including exceptions.

## Review steps

1. Identify each loop's condition, progress state, updates and exits. Trace relevant helpers and caller retry loops. Compare successive iterations on the same path.
2. Substitute EOF and zero-progress results. A negative read count can skip an inner copy loop and leave an outer position unchanged. Check explicit EOF handling and stale buffer state.
3. Track codec input/output positions. `CharsetEncoder.encode(..., false)` can return underflow with a trailing high surrogate still unconsumed, including with replacement configured. Check whether that branch consumes input, changes state or exits.
4. Compare counter and bound ranges. An `int` counter wraps after `2147483647`. Every possible `int` remains below a positive `long` bound of `2147483648L`. Establish that bound's reachability and inspect body exits. A `long` counter with a validated unsigned 32-bit bound refutes this overflow mechanism.
5. Track fallback values and the index at input boundaries. An index updated only while `index < length` can stay at `length`. A fallback sentinel satisfying the loop condition and an exit testing `index > length` can preserve that state. An effective `index >= length` exit refutes the path. A surrounding catch ends the loop only if that path throws.
6. Evaluate arithmetic updates using Java overflow and masked shift semantics. Check fixed points, repeated states, deadlines, interruption and lifecycle exits.

## Evidence and exclusions

State the trigger, repeated state and ineffective exit. Locate the loop or faulty update. Exclude finite expensive loops, blocking calls, recursion and intentional service loops with valid lifecycle controls. Describe eventual wraparound termination accurately. A counterexample that exits or throws refutes that path.
