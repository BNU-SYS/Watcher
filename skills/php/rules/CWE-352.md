### CWE-352: Cross-site request forgery

- Identify an operation that changes server state or performs a privileged action (insert, update, delete, password or email change, transfer, role assignment, approval) and takes its target or parameters from `$_GET`, `$_POST`, `$_REQUEST`, or `$_COOKIE` while the request is authenticated by an existing session or cookie.
- Report only when the supplied file shows no effective CSRF defense for that operation: no comparison against a session-bound token, no server-side re-authentication, and no verified framework middleware. A token that is read but never compared, compared with a value the client controls, or checked only for presence is not an effective defense.
- Read-only operations, intentionally public endpoints, and operations dominated by a verified token check are not findings.
- Do not infer the absence of a defense that the supplied file cannot show, such as a global middleware configuration; state the missing context as a limitation instead.

#### Finding location

- The primary operation is the state-changing call reachable from the request parameters without a verified CSRF token, such as the SQL write, file write, password or role update, or transfer operation. Explain the request parameter, the state change, and the absent token check.
