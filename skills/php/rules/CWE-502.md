### CWE-502: Deserialization of untrusted data

- Trace external input (`$_GET`, `$_POST`, `$_REQUEST`, `$_COOKIE`, the request body, or a file whose path is externally controlled) into `unserialize`, including after `base64_decode`, `urldecode`, `gzinflate`, `gzuncompress`, or `hex2bin`.
- Report when the serialized payload is attacker-influenced and no integrity control is visible: no signature or MAC verified with a server-side secret, and no class or type allowlist applied before deserialization.
- `json_decode` is not PHP object deserialization. A constant literal or a value read from a trusted configuration file is not externally controlled.
- Do not report when the payload is verified with a key the attacker cannot control; state missing key provenance as a limitation rather than assuming it is safe.

#### Finding location

- The primary operation is the `unserialize` call whose argument derives from external input. Explain the input path and the absent integrity or type control.
