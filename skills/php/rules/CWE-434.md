### CWE-434: Unrestricted upload of file with dangerous type

- Trace an uploaded file from `$_FILES[...]['tmp_name']`, `['name']`, or `['type']` into a persistence operation such as `move_uploaded_file`, `copy`, `rename`, or `file_put_contents`.
- Report when the stored name or extension is attacker-influenced and the visible validation is absent or bypassable: no extension whitelist, a blacklist of selected extensions, trust in the client-supplied `$_FILES[...]['type']`, or a check that does not constrain the final stored name or location.
- A server-side extension whitelist combined with a generated destination name, or storage outside the web root with no executable path, refutes the finding.
- Do not assume that an uploaded file is executable when the destination is not reachable by the web server; state that context as a limitation.

#### Finding location

- The primary operation is the call that stores the uploaded content, such as `move_uploaded_file`, `copy`, `rename`, or `file_put_contents`. Explain the attacker-controlled name or extension and the ineffective validation.
