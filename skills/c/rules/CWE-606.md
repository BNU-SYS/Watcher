### CWE-606: Unchecked Input for Loop Condition

#### Evidence required

Establish all of the following for the loop under review:

1. An externally supplied, configurable, hardware-derived, or otherwise exposed input source, supported by the supplied source, visible call chains, or an explicit interface contract.
2. A path by which that input controls the loop condition. Follow assignments, arguments, returns, and visible helpers, and identify the loop body or visible callee affected. Input acquisition need not occur in the same function or file when the supplied evidence establishes the path.
3. Missing or ineffective validation of that input for the loop's execution, such as an absent effective range limit, iteration budget, or termination constraint. Assess the protection of this loop and this input, including validation in visible callers or helpers.

These conditions are sufficient without an exact triggering value, proof of an infinite loop, a particular denial-of-service duration, or a memory-safety defect.

#### Exclusions and missing context

- A function parameter establishes data transfer, not the required input provenance by itself. Do not turn an unseen caller into evidence that arbitrary unvalidated input can reach the loop, and do not assume that unseen callers have validated it. If necessary provenance or validation context is missing, omit the candidate and record the material limitation.
- Check zero and negative bounds, induction-variable width, wraparound, progress, `break`/`return`, and loop guards. Exclude the candidate when a constant bound, a complete dominating range check, or another visible constraint effectively limits the relevant execution independently of the unchecked input.
- A limit on another value, operation, or loop excludes this candidate only when it demonstrably constrains this loop as well. Establish each protection's coverage from the supplied evidence.
- Parsing success, input acceptance, and numeric representability do not establish a permitted iteration count; a type's representable maximum is not an application-enforced iteration budget. External provenance alone also does not establish the defect without the propagation and missing-validation conditions above.

#### Finding location

- The primary operation is the loop condition controlled by the unchecked input. Explain the input-to-condition path and the missing effective constraint.
