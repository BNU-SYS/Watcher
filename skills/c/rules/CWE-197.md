### CWE-197: Numeric Truncation Error

#### Evidence required

Establish all of the following for the conversion under review:

1. An actual explicit or implicit conversion to a narrower numeric representation. Follow casts, assignments, arguments, return values, bit-fields, and arithmetic conversions.
2. The type and attainable range of the expression at that conversion. Apply the operators, integer promotions, and conversion rules to the complete expression; do not substitute a subexpression's type or range for the value actually being converted. Account for intermediate conversions separately when they themselves lose information.
3. A feasible value whose high bits or magnitude are lost or changed by the conversion. A visible out-of-range constant or helper return is sufficient. Explain the changed value or its visible use; a security-relevant downstream use strengthens severity but is not required when truncation is explicit.

#### Exclusions and missing context

- A cast, a wider declared type, or a function return type alone is insufficient without evidence of information loss at the actual conversion. If the necessary source range cannot be established, omit the candidate and record the material limitation.
- Built-in relational, equality, and logical operators produce truth values, not their operands' numeric values. In C their result is `int` with value `0` or `1`; in C++ it is `bool`. Storing such a result in a type that represents those values does not truncate the original operand. For conditional and other compound expressions, determine the resulting type and range under the applicable language rules; for overloaded C++ operators, use the visible return type and semantics.
- A fitting range proof, an effective checked conversion, or documented intentional narrowing refutes the candidate. Do not use this type for pure signedness without numeric truncation, or infer truncation from an unrelated arithmetic defect.

#### Finding location

- The primary operation is the explicit or implicit narrowing conversion that loses numeric information, including an assignment, argument conversion, or return conversion. Explain the source value, target type, and changed value or subsequent use.
