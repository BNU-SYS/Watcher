### CWE-362: Race Condition

#### Evidence required

Establish all of the following for the conflict under review:

1. Two conflicting read/write or write/write accesses to the same or overlapping memory location in a global or process-shared object. Identify both accesses and the functions or entry points that perform them.
2. Evidence that the accesses may execute concurrently. Visible starts through `pthread_create`, `thrd_create`, `std::thread`, or an equivalent API can establish this possibility; inspect visible synchronization and ordering without requiring a scheduler trace. The accesses may come from different functions or concurrent invocations of the same function.
3. At least one non-atomic access and no effective common synchronization protecting the conflicting accesses. Check lock identity and scope, acquisition on each relevant path, atomic operations, thread confinement, interrupt exclusion, and visible happens-before relations.

#### Exclusions and missing context

- Resolve the actual memory location, including structure members, array elements, and aliases. A conflict on one member does not establish a conflict on another. Accesses to distinct, non-overlapping memory locations do not establish this conflict merely because they belong to the same aggregate. Account for whole-object accesses, unions, bit-fields, and aliases when they make the locations overlap or share a language-defined memory location.
- A global declaration, one unprotected access, or the existence of multiple functions or threads does not supply a missing conflicting access. Do not invent another access, an overlapping invocation, or a future extension. If a necessary access, concurrency relation, alias relation, or synchronization contract cannot be established, omit the candidate and record the material limitation.
- Exclude a conflict when visible synchronization or ordering protects both accesses on the relevant paths. Check initialization and callback context as applicable. A locked read copied to a local and used only after unlocking is not by itself a race.

#### Finding location

- The primary operation is one actual shared-memory read or write participating in the supported conflict. Variable declarations, lock declarations, and thread creation are supporting evidence unless they themselves perform a demonstrated conflicting access. Report one Finding for the same supported conflict and identify the other access, concurrency evidence, and missing common synchronization in `explanation`.
